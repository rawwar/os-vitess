Part II · Chapter 15

Don't edit that file.

Vitess has a lot of generated code. Editing the wrong file silently gets reverted on the next codegen. Here's how to tell.

Learning objectives

By the end of this chapter, you will
  • Spot a "DO NOT EDIT" file at a glance.
  • Know which command regenerates protobufs vs. sqlparser AST.
  • Use gofumpt and goimports before every commit.
  • Use vterrors.Errorf instead of fmt.Errorf for new errors.

The DO NOT EDIT banner

// Code generated by ... DO NOT EDIT.
  • If a file starts with this banner, don't touch it.
  • Find the source (a .proto, .y, AST defn, or generator script).
  • Edit the source. Re-run the generator. The generated file updates.
House rule
From CLAUDE.md: "Never directly edit files with a 'Code generated ... DO NOT EDIT' header — these are generated and will be overwritten."

The two main codegen pipelines

protobufs

  • Source: proto/*.proto
  • Output: go/vt/proto/<name>/
  • Regenerate: make proto

sqlparser AST

  • Source: go/vt/sqlparser/ast.go + sql.y
  • Output: ast_clone.go, ast_equals.go, ast_format_fast.go, ast_path.go, ast_rewrite.go, ast_visit.go, cached_size.go, sql.go
  • Regenerate: make codegen

Other generated bits to know

  • go/vt/sqlparser/sql.go — yacc output from sql.y.
  • cached_size.go in many packages — memory accounting via go generate.
  • mock_*.go files — gomock-generated.
  • go/flags/endtoend/*.txt — golden flag output, regenerated when CLI flags change. Whitespace-sensitive.

Protobuf rules (from CLAUDE.md)

  • Edit proto/*.proto, run make proto.
  • For timestamps, use vttime.Time, not raw int64.
  • For durations, vttime.Duration or google.protobuf.Duration.
  • For tablet aliases, use topodata.TabletAlias, not strings.

These choices propagate everywhere — pick wrong and you'll touch hundreds of files later.

Formatting requirements

gofumpt -w <changed-files>
goimports -local "vitess.io/vitess" -w <changed-files>
  • gofumpt — strict superset of gofmt. Mandatory.
  • goimports with -local "vitess.io/vitess" — groups Vitess imports separately from stdlib and third-party.
  • CI will reject PRs that fail these.

Set up your editor to run them on save. (For VS Code, the Go extension can do both.)

Error handling: vterrors

// YES
return nil, vterrors.Errorf(
    vtrpcpb.Code_FAILED_PRECONDITION,
    "user ID cannot be empty",
)

// YES (wrap)
return vterrors.Wrapf(err, "failed to get user %s", id)

// NO — bare errors lose gRPC code propagation
return fmt.Errorf("user not found")

Errors must carry a gRPC code. Pick the right one — clients dispatch on it. Common ones: INTERNAL, INVALID_ARGUMENT, FAILED_PRECONDITION, UNAVAILABLE, RESOURCE_EXHAUSTED.

Logging

  • New code: use structured logging — log.Info("msg", slog.String("key", "value"))
  • Old code: uses printf-style log.Infof("...") — leave it unless changing the line anyway
  • Format tablet aliases via topoproto.TabletAliasString(alias), not %v on the proto
  • Always log the original error before recovery attempts

Flags

  • No underscores in flag names. --my-flag, not --my_flag.
  • Use pflag (cobra) for new commands.
  • Adding a flag? Update the golden file under go/flags/endtoend/<binary>.txt. Column alignment matters.
  • Validate mutually exclusive flag combos in PreRunE.

Testing conventions

  • github.com/stretchr/testify/assert and .../require
  • require when "can't continue" (e.g., after a successful setup); assert otherwise
  • t.Context() not context.Background()
  • assert.Eventually not manual sleep loops
  • Generous timeouts (30s+) — CI runners are flaky on short timeouts
  • _test.go suffix for helpers used only by your package; testutil/ sub-package if shared

Commits & PRs

  • DCO sign-off: every commit needs git commit --signoff.
  • Imperative-mood commit messages, short subject + body explaining why.
  • Small PRs are merged faster than big ones.
  • User-visible behavior changes need a release note under changelog/.
  • Never amend a commit after pushing to a PR branch — append new commits instead.

Try it yourself

Spot the generated files
  1. head -5 go/vt/proto/topodata/topodata.pb.go — see the DO NOT EDIT banner.
  2. head -5 go/vt/sqlparser/ast_clone.go — same.
  3. head -5 go/vt/sqlparser/ast.go — handwritten, no banner.

Checkpoint quiz

1. You opened go/vt/proto/topodata/topodata.pb.go and want to add a field. What do you do?
Reveal
Close it. Edit the corresponding .proto file under proto/. Then make proto. The .pb.go file regenerates automatically.
2. You added a flag --my_new_flag. CI rejects it. Why?
Reveal
Flag names use hyphens, not underscores: --my-new-flag. Also remember to update the golden file under go/flags/endtoend/<binary>.txt if the flag is on a long-running binary.
3. Two commands you must run before git commit on any Go file?
Reveal
gofumpt -w <files> and goimports -local "vitess.io/vitess" -w <files>. Many editors run both on save; configure yours.

Recap

You should now be able to
  • Spot generated files before wasting time editing them.
  • Re-generate after editing protos or AST source.
  • Pass CI's formatting and lint checks on the first push.
