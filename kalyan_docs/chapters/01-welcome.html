Why we start with MySQL

Vitess is not a new database. It's a layer that sits in front of vanilla MySQL servers and orchestrates them. Without understanding MySQL's wire protocol, binary log, and replication, the Vitess code looks like magic.

Part I (chapters 2-6) is the MySQL foundation. Skim it if you're already deep on MySQL; read it twice if you're not.

"If you can't replicate the bug against plain MySQL, the bug probably is Vitess. If you can, the bug is below Vitess and you need to know what's down there."

Checkpoint quiz

1. Why does this course start with MySQL chapters before any Vitess code?
Reveal
Vitess is a layer above MySQL. Every Vitess subsystem (planner, vttablet, VReplication, online DDL) references binlogs, GTIDs, transactions, or the wire protocol. You can't read Vitess source without those words being concrete.
2. What's the "code-along mindset"?
Reveal
Read this site in one window, open the Vitess repo in your editor in another. Every code citation points at a real file. Jump to it. Reading without jumping doesn't stick.
3. What was that famous quote about debugging?
Reveal
"If you can't replicate the bug against plain MySQL, the bug probably is Vitess. If you can, the bug is below Vitess and you need to know what's down there." The MySQL chapters teach you the "below" half.
