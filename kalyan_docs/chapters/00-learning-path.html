Where this course takes you

Vitess is not a new database. It is a layer that sits in front of plain MySQL servers and orchestrates them — routing queries, managing replication, copying rows between shards, handling failovers. To read its source code well, you need to understand three things in order: the database concepts Vitess depends on, the MySQL internals it builds on, and the Vitess components that tie them together.

flowchart TB Foundations[Foundations
SQL · DB internals · Go reading · Terminal] MySQL[MySQL internals
indexes · binlog · replication · protocol] Vitess[Vitess
vtgate · vttablet · sharding · workflows] Foundations --> MySQL MySQL --> Vitess

Most readers won't keep all of it in their head on first pass. That's expected. The way to learn a complex system is to revisit the same idea from three different angles — once when you meet it, once when you see it in code, once when you debug it — until it sticks. Every part of this course is designed to be revisited.

By the time you reach Part VI (Contributing to Vitess), you should be comfortable opening any file in go/vt/ and figuring out roughly what it does. That's the bar.

Who this is for

This course assumes very little. You need to have written a SELECT with a WHERE clause, you need to be reasonably comfortable in a terminal, and you need to be able to clone a Git repo and run a shell script. That's it.

You do not need to know Go. You do not need to know MySQL internals. You do not need any background in distributed systems. You certainly do not need to have used Vitess before. If you have any of that, you'll move faster — skim Part 0 and start at Part I. If you don't, follow the chapters in order; the pace is gentle on purpose.

You bring

  • Basic SQL: SELECT, WHERE, maybe a JOIN.
  • A working terminal.
  • Curiosity about how databases actually work.

You'll leave with

  • A working mental model of MySQL internals.
  • The ability to read and navigate a Go codebase the size of Vitess.
  • A clear map of every Vitess component and what it does.
  • Enough context to file a real PR.

What this course is — and is not

This course is code-focused. Every concept points at a real file. Every claim has a code path you can verify. We deliberately resist the temptation to explain Vitess only through diagrams and analogies — those help, but they're not enough to make you an effective contributor. When something is fuzzy, the cure is usually to open the file the chapter cites and stare at it for ten minutes.

This course is not a substitute for the official documentation at vitess.io/docs. Those docs are operator-focused — they tell you how to run Vitess in production. This course is contributor-focused — it tells you how to change Vitess. Keep both open. They complement each other.

"If you can't replicate the bug against plain MySQL, the bug probably is Vitess. If you can, the bug is below Vitess, and you need to know what's down there."

That quote captures the whole reason Part 0 (foundations) and Part I (MySQL) come before any Vitess code. Skipping them is technically allowed; it just makes everything afterwards harder.

How to read a chapter

Every chapter follows the same shape. Once you recognize it, you can decide for each section whether to skim or deep-read.

  1. Hero — title, part tag, one-line framing.
  2. Objectives — a four-bullet list of what you'll be able to do by the end. Use it as a self-test.
  3. Narrative sections — each one bridges from the previous, develops one idea over a few paragraphs (with diagrams and code inline), and closes with a takeaway.
  4. Worked example — at least one detailed walked-through example so the abstractions get concrete.
  5. Lab — hands-on commands with expected output. Optional but strongly recommended.
  6. Misconceptions — the most common wrong assumptions, called out so you don't make them.
  7. Quiz — three to five questions with reveal-on-click answers. Honest self-check, not graded.
  8. Recap — the summary card. If you can't recite this, re-read the chapter.
  9. Further reading — external links and code pointers for the obsessed.

You can jump to any section using the chapter Table of Contents that sits beneath the topbar in docs view.

Use the glossary, especially early on

Any word with a dashed underline is a glossary term. Hover or tap it for an instant definition. The glossary covers everything from foundational SQL terms to Vitess-specific concepts — about fifty terms in total. Press g at any time to open the full glossary drawer, which you can search.

Try it now. Hover over each of these and read the definition:

  • binlog — the MySQL log file Vitess hooks into.
  • shard — one slice of data.
  • vindex — the function that maps a row to a shard.
  • vtgate — Vitess's query router.

If you ever get lost on what a word means, don't read past it. Misunderstanding a key term compounds. Stop, hover, and only then continue.

Two views: docs and presentation

By default, this site renders each chapter as a scrollable docs page — easy to read at length, easy to search, easy to skim. The Table of Contents at the top lets you jump between sections.

If you prefer slide-style reading — one idea per screen, arrow keys to navigate, full-screen mode — click the ◧ Slides button in the top right (or press v). Your preference saves and persists across chapters. Switch back any time. The content is identical in both views; only the presentation differs.

When each view shines
Docs mode is better for first-pass reading, code-along sessions, and search. Slides mode is better for review, presentations, or when you want to absorb one concept at a time without scrolling distractions.

Quick check: read a SQL query

Before chapter 2 dives into SQL formally, let's confirm where you are. Given this tiny customer table:

customer_id | email                | country
1           | alice@example.com    | US
2           | bob@example.com      | IN
3           | carol@example.com    | US

What does this query return?

SELECT COUNT(*) FROM customer WHERE country = 'US';
Reveal the answer
2 — two rows where country = 'US' (Alice and Carol). If you got it instantly, you're ready. If you had to think, that's fine — chapter 2 is a SQL refresher. If the question itself felt confusing, read chapter 2 carefully and try the warm-up lab at the end of it.
