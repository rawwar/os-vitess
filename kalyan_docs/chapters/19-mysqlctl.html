Part IV · Chapter 24

The process manager.

Starts, stops, configures, backs up, restores the actual mysqld binary. Where SQL meets Unix.

Learning objectives

By the end of this chapter, you will
  • Tell apart mysqlctl (CLI) and mysqlctld (daemon).
  • Find where my.cnf is generated and how to extend it.
  • Locate the sidecar schema (_vt) inside any tablet's mysqld.

Two binaries, one library

  • mysqlctl — CLI, one-shot commands (init, start, shutdown).
  • mysqlctld — daemon, exposes the same commands as gRPC.
  • Both wrap the library at go/vt/mysqlctl/.
  • vttablet talks to mysqlctld over gRPC when it wants to start/stop the mysqld.

Why split? Some environments (Kubernetes) prefer the colocated daemon model.

Key files

  • go/vt/mysqlctl/mysqld.go — the Mysqld struct, central object.
  • go/vt/mysqlctl/cmd.go — command dispatch.
  • go/vt/mysqlctl/mycnf.go — generates my.cnf from a template.
  • go/vt/mysqlctl/backup.go — backup orchestration.
  • go/vt/mysqlctl/replication.go — replication SQL helpers.

Initializing a mysqld

mysqlctl init
  1. Generate a my.cnf from the template & flags.
  2. Create the data dir.
  3. Run mysqld --initialize to create system tables.
  4. Start mysqld.
  5. Apply the Vitess sidecar schema (a special database for VReplication, online DDL, etc.).

The sidecar schema is in go/vt/sidecardb/.

my.cnf generation

  • config/mycnf/ — templates per MySQL flavor (8.0, 8.4, MariaDB).
  • Templates use Go's text/template with substitutions for paths, port, server-id, etc.
  • vttablet generates the cnf on first start, then re-uses it across restarts.

Customize per-environment via --mysql_server_extra_cnf flags (don't edit the template).

Backups: the boring importance

  • vttablet → tabletmanager Backup RPC → mysqlctl → backup engine.
  • Two engines:
    • builtin — file-by-file copy via VReplication-style snapshot.
    • xtrabackup — wraps Percona XtraBackup for hot backups.
  • Storage abstractions:
    • filebackupstorage/ — local disk
    • gcsbackupstorage/ — Google Cloud Storage
    • azblobbackupstorage/ — Azure
    • cephbackupstorage/ — S3-compatible Ceph

Restore

  • vttablet on a fresh box detects "no data dir, but topo says there should be a tablet here".
  • Calls RestoreFromBackup: download the most recent backup, replay binlogs to catch up.
  • vttablet then continues as a replica.
  • The whole flow is what makes Vitess "self-healing": a dead replica gets reborn automatically.

Replication helpers

go/vt/mysqlctl/replication.go wraps the SQL:

  • SetReplicationSource → CHANGE REPLICATION SOURCE TO ...
  • StartReplication → START REPLICA
  • StopReplication → STOP REPLICA
  • ReplicationStatus → SHOW REPLICA STATUS parsed into a struct
  • PrimaryPosition / WaitForPosition → GTID work

The flavor abstraction (chapter 5) means these helpers Just Work on MariaDB / MySQL 5.6 / 8.x.

Sidecar schema

  • Vitess needs a few tables in your mysqld for its own bookkeeping.
  • Examples: _vt.vreplication, _vt.schema_migrations, _vt.copy_state.
  • Managed by go/vt/sidecardb/; auto-migrates on startup.
  • If you're debugging VReplication or online DDL, this is where the state lives.

vtbackup: the standalone backup tablet

  • go/cmd/vtbackup/ — a one-shot binary.
  • Used in K8s / cron contexts: spin up a tablet, restore the latest backup, take a fresh backup, exit.
  • Lets you take backups without dedicating a tablet to "backup duty" full time.

Try it yourself

Recap of Part IV

  • vttablet has two halves: query path (tabletserver) and control path (tabletmanager).
  • VTOrc watches replication, calls vtctld to fix it.
  • ERS/PRS are composed from primitive tabletmanager RPCs.
  • mysqlctl is the layer that actually starts mysqld and runs the SQL.

Checkpoint quiz

1. Why is there both mysqlctl and mysqlctld?
Reveal
mysqlctl is a one-shot CLI useful for init/shutdown scripts. mysqlctld is a long-running daemon that exposes the same commands as gRPC — better in Kubernetes or environments where vttablet shouldn't fork mysqld directly.
2. What's inside the _vt schema on every Vitess-managed mysqld?
Reveal
VReplication state (_vt.vreplication), online DDL state (_vt.schema_migrations), copy state, heartbeats. The sidecar schema is Vitess's bookkeeping inside the database it manages.
