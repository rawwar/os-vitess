Part II · Chapter 14

From source to a running cluster.

No amount of reading replaces running it yourself. By the end of this chapter you'll have a real Vitess cluster on your laptop and queried it through vtgate. This is the chapter you'll come back to whenever you want to test an idea.

Learning objectives

By the end of this chapter, you will
  • Have built every Vitess binary from source.
  • Have a 5-tablet local cluster running on your laptop.
  • Have queried it through vtgate as if it were plain MySQL.
  • Have tailed a vttablet's log while running a query and seen the exact moment your SQL hits mysqld.
  • Know how to tear it all down and start fresh.

Prerequisites

  • Go — version pinned in go.mod (go 1.24+ at time of writing).
  • MySQL or Percona — Vitess talks to a real mysqld. Install MySQL 8.x from your package manager.
  • etcd — local example uses etcd as the topo. The bootstrap script provides one.
  • protoc — only if you'll regenerate protobufs. Skip if you're just building.
  • make, bash, ~3-4 GB free disk.

macOS or Linux. Windows works through WSL only.

One-time setup

# From the repo root:
./bootstrap.sh        # installs proto compiler, dev tools, etcd into vthook/
source dev.env        # sets VTROOT, VTDATAROOT, PATH, etc.
make build            # compiles all binaries into bin/
  • bootstrap.sh is idempotent — re-run after a rebase if dev tools change.
  • dev.env is sourced into your shell. Re-source after opening a new terminal.
  • Binaries land in bin/. That dir is on PATH via dev.env.

The Makefile is your friend

The local example: top to bottom

cd examples/local
source ../common/env.sh
./101_initial_cluster.sh

That single script:

  1. Starts etcd as the topo service.
  2. Starts vtctld.
  3. Starts five vttablets (one primary + replicas for the commerce keyspace).
  4. Initializes the keyspace schema.
  5. Starts vtgate.
  6. Starts vtorc.

You now have a cluster on localhost. mysql -h 127.0.0.1 -P 15306 connects to vtgate.

What's running

ps aux | grep -E 'etcd|vt(gate|tablet|ctld|orc)'
# you'll see:
#   etcd (topo)
#   vtctld
#   vttablet x 5
#   vtgate
#   vtorc

Process logs land in $VTDATAROOT/tmp/. This is your friend when something is wrong.

Tail a vttablet's log
tail -f $VTDATAROOT/tmp/vttablet_*.INFO — watch real RPCs go by while you query vtgate.

The scripted progression

ScriptWhat it demonstrates

202_move_tables.shVReplication: copy customer + corder tables to it
203_switch_reads.sh / 204_switch_writes.shCut traffic over

Each script is short (~50-100 lines) and uses vtctldclient primitives. Read them.

Watching code live

  1. Connect: mysql -h 127.0.0.1 -P 15306
  2. Run: SELECT * FROM customer;
  3. In another terminal, tail: tail -f $VTDATAROOT/tmp/vtgate.INFO
  4. You'll see the query, the chosen plan, the route, the latency.
vtgate /debug pages
open http://localhost:15001/debug/status (port for vtgate, varies). The web pages expose status, stats, query log, plan cache — invaluable.

Lab 2: bring up the cluster Lab · 5 min

Boot the demo
  1. cd examples/local
source ../common/env.sh
./101_initial_cluster.sh
  2. Wait ~30 seconds for "successfully initialized". You now have etcd, vtctld, 5x vttablet, vtgate, vtorc.
  3. Confirm processes: 
    ps aux | grep -E '(etcd|vt(gate|tablet|ctld|orc))' | grep -v grep | wc -l
Expected — you should see 8 processes
8
(1 etcd + 1 vtctld + 5 vttablet + 1 vtgate + 1 vtorc = 8 unique processes)

Lab 3: query through vtgate Lab · 5 min

Talk to Vitess like it's MySQL
  1. Connect: 
    mysql -h 127.0.0.1 -P 15306 --table
    Port 15306 is vtgate's MySQL listener. The app thinks it's MySQL.
  2. List tablets: 
    SHOW VITESS_TABLETS;
  3. Look at the commerce keyspace: 
    USE commerce;
SHOW TABLES;
SELECT * FROM customer LIMIT 5;
Expected (truncated)
+--------------+
| Tables       |
+--------------+
| corder       |
| customer     |
| product      |
| ...          |
+--------------+

Notice you didn't have to know which shard or tablet to talk to. vtgate routed it for you.

Lab 4: watch a query land on a tablet Lab · 10 min

See your SQL hit mysqld
  1. In one terminal, tail a vttablet log: 
    tail -f $VTDATAROOT/tmp/vttablet_0000000100.INFO
    (Pick any of the vttablet_*.INFO files. 0000000100 is the first one.)
  2. In another terminal, run a query through vtgate: 
    mysql -h127.0.0.1 -P15306 -e "SELECT * FROM commerce.customer LIMIT 3"
  3. Watch the log scroll. You'll see at least one log line matching your query, with timing.
  4. Also try the debug pages: open http://localhost:15001/debug/status (vtgate). Then find a vttablet's port from SHOW VITESS_TABLETS and open its /debug/status too.
What to notice
  • Only one vttablet sees the query — vtgate picked the primary for the keyspace.
  • The /debug/status pages on vtgate and vttablet are gold mines: live stats, recent queries, plan cache, current state.

Lab 5: tear it down Lab · 1 min

Clean state matters
  1. ./501_teardown.sh
    Stops every process and removes the $VTDATAROOT tree.
  2. Confirm: 
    ps aux | grep -E '(etcd|vt(gate|tablet|ctld|orc))' | grep -v grep
    should show nothing.

You'll re-run ./101_initial_cluster.sh dozens of times across this course. The cluster is a scratchpad — feel free to break it.

Troubleshooting Common issues

SymptomLikely causeFix
command not found: mysqldMySQL not installed or not on PATHmacOS: brew install mysql. Linux: apt install mysql-server.
address already in use for ports 15306/15001/2379Old cluster still up./501_teardown.sh, then lsof -i :15306 to confirm.
error setting up etcdEtcd binary missingRe-run ./bootstrap.sh to re-install it into vthook/.
"Schema engine error" on tablet startupStale VTDATAROOTrm -rf $VTDATAROOT/vt_*, then re-run cluster start.
vtorc keeps re-parenting / log spamOne tablet didn't come up cleanlyCheck that tablet's .INFO log; usually mysqld init failed.
"too many open files"OS file-descriptor limit too lowulimit -n 10000 in your shell.
macOS firewall popup for each binarySystem securityAllow incoming for each prompt. Or pre-set VTDATAROOT under your home dir to silence them.

Checkpoint quiz

1. Which port does vtgate listen on for MySQL clients in the local example?
Reveal
15306. The 15 prefix is the convention in the example to avoid clashing with real local MySQLs on 3306.
2. After running ./101_initial_cluster.sh, how many vttablet processes should be running and why?
Reveal
Five. The commerce keyspace has one primary tablet and four others (replica + rdonly) for read scaling and failover demos.
3. You want to test a code change to vtgate. What's the rebuild-and-restart loop?
Reveal
make build → ./501_teardown.sh → ./101_initial_cluster.sh. Each takes about a minute. There's no live reload — vtgate restarts pick up the new binary from bin/vtgate.
4. Where do all process logs land?
Reveal
$VTDATAROOT/tmp/. Files named like vtgate.INFO, vttablet_0000000100.INFO, etc. Tail them while you debug.
